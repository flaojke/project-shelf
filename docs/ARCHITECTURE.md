# Архитектура

`React/TypeScript в WebView2 ⇄ Tauri IPC ⇄ Rust Supervisor → четыре адаптера`.

Frontend собирается Vite в статический `dist` и встраивается в EXE. Собственного HTTP backend у Project Shelf нет. Node используется только адаптером веб-проекта. UI состоит из карточек, настройки профилей, страницы диагностики и журнала; оформление — обычный CSS и собственные SVG.

Supervisor сериализует действия каждого профиля через Tokio Mutex, проверяет полноту конфигурации до любых probes/CLI и хранит состояния `setup`, `stopped`, `starting`, `ready`, `external`, `stopping`, `error`, `unavailable`. Пустые профили не запускают инструменты. IDs и типы четырёх профилей фиксированы; путь/runtime/health-параметры задаются пользователем. Конфигурацию управляемого работающего ресурса менять нельзя до его остановки; избранное менять можно.

## Адаптеры

- **Process / Vite:** embedded JS-мост атомарно размещается в AppData runtime, импортирует Vite API выбранного проекта и сохраняет его config. Host —127.0.0.1, strictPort, браузер открывается после readiness. Команда stdin `shutdown` закрывает сервер и позволяет циклу событий завершить ожидающие операции. EOF означает Leave. Дочерний `CI=true` отключает внутренний EOF-exit Vite, не меняя ОС или `.env`.
- **PowerShell:** исполняется только `start-site.ps1` из выбранной папки с фиксированными структурированными аргументами. Health identity включает service/root/port/ready/PID. Владение сервером не присваивается, принудительная остановка недоступна.
- **Docker:** один сервис точного Compose-файла, без pull/build/dependency startup. При необходимости запускается существующий Docker Desktop. Владение доказывается полными container IDs и labels; Stop адресует только сохранённые IDs. Другие сервисы, Desktop и volumes не удаляются.
- **Android:** SDK, AVD и package/activity задаются пользователем. Выбор устройства адресный; не используется первое попавшееся ADB-устройство. Проверяются boot_completed, AVD и PID. Установка APK отдельна от открытия; uninstall/clear/wipe не используются.

## Данные и границы

Профили и настройки — JSON в собственном AppData; запись через временный файл и атомарную замену. Недавние — localStorage WebView. Журнал — ограниченное кольцо в памяти текущего сеанса; сырой stdout/stderr и переменные окружения в UI не выводятся. Секреты в профили не принимаются.

Долгие процессы отслеживаются Windows Job Objects без kill-on-close. Владение не переносится между сеансами: после перезапуска прежние ресурсы внешние. Stop всегда проверяет принадлежность ресурса; конфликты портов не решаются завершением чужих процессов. Watchdog конечных CLI может завершить только собственный инструмент по таймауту.

Трей и полный выход разделены. Крестик показывает диалог; выбор Leave сохраняет проекты. Single-instance восстанавливает существующее окно. Автозапуска ОС нет.

HTTP разрешён только на loopback, без credentials/query/fragment; redirects и proxy для health выключены. В UI нет произвольных shell-команд. JSON-схемы и поля конфигурации валидируются в Rust; frontend-проверки не заменяют backend authority.

Конфигурация рассчитана на совместимые Vite/PowerShell/HTTP-Docker/Android системы. Это не универсальный менеджер любых процессов и не среда сборки проектов.
