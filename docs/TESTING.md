# Проверки

Тесты рассчитаны на Windows и Node.js 24+. Используются встроенный Node Test Runner, Playwright и Rust unit tests.

## Без запуска пользовательских систем

`npm test` проверяет API, неполную/валидную конфигурацию, отказ действий до настройки и жизненный цикл настоящего Node bridge на временном mock Vite API. Fixtures создаются в системном Temp; тестовые HTTP-серверы используют loopback. Очистка ограничена собственным временным каталогом.

`npm run test:ui` проверяет demo/mocked native UI: первые четыре setup-карточки, формы и validation, сохранение без запуска, поиск, избранное, страницу журнала, окно/выход и блокировку изменения управляемого ресурса. По умолчанию используется Microsoft Edge. Приложения и SDK пользователя не запускаются.

`cargo test --manifest-path src-tauri/Cargo.toml --locked` проверяет backend production helpers, пустую конфигурацию и её guards, профили/JSON, адреса/пути, владение ресурсами и ограниченные команды адаптеров. Не запускайте пользовательские интеграции из обычного CI. Реальные lifecycle-проверки требуют отдельной подготовленной тестовой среды и явного согласия владельца.

## Ручная проверка собственного стенда

Используйте отдельные временные проекты/данные. Начните с четырёх пустых профилей: статус setup, никакого запуска до настройки. Проверьте сохранение части полей, корректные ошибки, заполнение всех обязательных полей и отдельный Start. Внешний процесс, контейнер или эмулятор не останавливайте ради теста.

Проверьте повторный Start, конфликт порта, Stop только своего ресурса, Leave с сохранением сервера и повторный запуск Shelf. Для Android используйте одноразовый тестовый AVD; не очищайте данные личного устройства. Для Docker не удаляйте тома и не останавливайте Desktop.

Успешная компиляция не означает, что тестовый бинарник выполнен. Прерванный, пропущенный или не запущенный прогон должен быть отмечен отдельно от passed. Не отключайте защитные политики системы ради тестов.
