# Windows review build

`.github/workflows/windows-build.yml` собирает проверочный комплект в приватном GitHub-репозитории. Workflow запускается только вручную через `workflow_dispatch`; загрузка исходников не является командой его запуска. Публичный релиз, публикация пакетов и подпись кода в нём не настроены.

## Перед запуском

1. Убедитесь, что выбраны нужные GitHub account, приватный репозиторий и проверенный commit. Если предлагаемое имя занято, сначала определите владельца и назначение существующего репозитория.
2. В GitHub Billing проверьте оставшийся included compute и allowance хранения артефактов. Включённая квота используется всем аккаунтом и не определяется только этим репозиторием.
3. Подтвердите, что платный перерасход заблокирован. Одни бюджетные уведомления этого не обеспечивают. Отсутствие подтверждения означает, что workflow запускать нельзя.
4. После проверки выберите Actions → Private Windows review build → Run workflow и подтвердите `free_quota_confirmed`. Этот input фиксирует ручное подтверждение, а не заменяет проверку billing.

Официальные правила: [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [runner pricing](https://docs.github.com/en/billing/reference/actions-runner-pricing), [budgets](https://docs.github.com/en/billing/how-tos/set-up-budgets). Сведения о платежах и личных данных не добавляются в исходники или артефакты.

## Что выполняется

- Один стандартный Windows x64 job, без матрицы и сохраняемых caches, с таймаутом 60 минут. Повторный ручной запуск отменяет предыдущий запуск этого workflow. Таймаут ограничивает время работы, но не доказывает отсутствие расходов.
- Только `contents: read`; checkout не сохраняет credentials. Официальные checkout, setup-node и upload-artifact закреплены полными SHA.
- `.gitattributes` отключает преобразование окончаний строк: проверенные исходники и сторонние legal-тексты сохраняют байты при первом commit и checkout. Их SHA проверяются повторно.
- Проверка tracked source: четыре обезличенные PNG-обложки, пустые профили и отдельный public application ID. Профили пользователя, SDK, базы приложений, runtime и исполняемые файлы в исходники не принимаются.
- Node.js 24.22.2, `npm ci --ignore-scripts`, тесты проверяющего скрипта, Node mock-тесты, сборка интерфейса и Playwright с mock IPC.
- Rust 1.99.1, `cargo test --locked --lib`, затем Tauri EXE и NSIS. Пользовательские приложения, контейнеры, SDK и эмуляторы тестами не запускаются.
- Remapping путей компиляции и отключение release debug symbols. Проверяются версии и Authenticode status файлов, без запуска EXE.
- Повторная проверка неизменности tracked source, готового frontend, EXE, NSIS и извлечённого установочного payload. Это поиск известных форм секретов/локальных путей и метаданных, а не доказательство отсутствия любого скрытого содержимого.

Обязательные обложки: `src/assets/covers/android-cover.png`, `web-cover.png`, `powershell-cover.png`, `docker-cover.png`. Если финальные изображения отсутствуют или PNG содержит текстовые/EXIF-метаданные, проверка останавливает комплект для рассмотрения. Заглушки автоматически не создаются.

## Результат

После успешных проверок сохраняется один артефакт `project-shelf-windows-<commit SHA>` на один день. Некомпрессированный комплект ограничен 96 MiB. В него включены только EXE, NSIS installer, LICENSE, NOTICE, THIRD_PARTY_NOTICES, каталог licenses и `BUILD-MANIFEST.json` с commit, workflow run ID и SHA-256 файлов. Build caches, исходники SDK, отладочные символы и тестовые журналы в этот артефакт не добавляются.

Полный успешный CI run не означает, что файлы подписаны или прошли ручную нативную приёмку. Скачанный комплект необходимо сверить с конкретным commit и manifest, проверить, затем открыть именно этот нативный EXE с пустыми профилями для приёмки. Любые ограничения локального запуска требуют отдельного решения; workflow не меняет настройки компьютера.

## Локальная проверка helper

`node --test scripts/ci-verify.test.mjs` выполняет только проверки на синтетических данных. Команды `node scripts/ci-verify.mjs source` и `package` предназначены для утверждённого GitHub Actions run и проверяют соответствие checkout commit. Они не являются командой установки или запуска приложения.
