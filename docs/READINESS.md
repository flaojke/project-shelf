# Технологии, готовность и управление

Карточки показывают технологии адаптера запуска: Vite/Node.js, PowerShell/HTTP, Docker/Compose или Android/ADB. Точные версии React и Vite выводятся в деталях только при чтении установленных package.json проекта. Выбор адаптера сам по себе не подтверждает наличие его зависимостей.

В деталях четыре независимые проверки:

| Поле | Что подтверждается |
|---|---|
| Компоненты запуска | Наличие нужных файлов и инструментов; для Docker — доступность CLI/Engine, для Android — SDK и существующего ADB-сервера |
| Процесс или сервис | Собственный процесс Windows Job, identity контейнера или выбранное Android-устройство/приложение; внешний PID не присваивается Shelf |
| HTTP-ответ | Фактически полученный код и соответствие identity профилю; общий статус «готов» не превращается в HTTP 200 |
| Локальный порт | Результат подключения и проверки endpoint; конфликт не освобождается принудительно |

Состояния: «Проверяем», «Не проверено», «Готово», «Ошибка», «Не требуется». Для Android HTTP и порт веб-сервера не применяются. Незавершённая настройка публичного профиля не запускает инструменты. Диагностика не устанавливает зависимости, не включает Docker Engine, не запускает AVD и не устанавливает APK. Измерения имеют время проверки; невозможность измерения остаётся видимой.

«Перезапустить» удерживает блокировку проекта на всём последовательном Stop → Start. Повторный запрос не ставится в очередь. Новый запуск выполняется только после успешной остановки и повторной проверки, что приложение не выходит. При ошибке остановки новый ресурс не запускается. Внешний процесс, контейнер или эмулятор не присваивается текущей сессии.

Кнопки управления доступны только после подтверждения соответствующей возможности и владения ресурсом. Для PowerShell-сайта безопасного shutdown-контракта нет: Stop и Restart отключены с объяснением, принудительное завершение запрещено. Остановка ресурсов не удаляет тома, данные Android или файлы проектов.

Журнал содержит структурированные события текущего проекта. При смене карточки запоздавший ответ прежнего проекта не добавляется в новый журнал. Сырой stdout/stderr, содержимое environment и данные приложений в журнал не копируются.

Проверки с mock IPC и браузерным demo подтверждают поведение интерфейса отдельно от нативного диспетчера. Успешная сборка интерфейса не подтверждает Rust-сборку, реальные lifecycle-интеграции или обновление установленного EXE.
