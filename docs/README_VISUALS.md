# Визуальные материалы README

## Настоящие снимки интерфейса

Скриншоты получены из текущего React-приложения в изолированном браузерном контексте Microsoft Edge. Используется browser demo с пустыми профилями. Системные процессы, личные проекты, SDK и контейнеры не запускаются. Статусы на снимках не являются подтверждением нативной готовности.

После установки зависимостей запустите из корня репозитория:

```powershell
node scripts/capture-readme.mjs
```

Скрипт занимает только loopback-порт 1422, создаёт три PNG в `docs/assets`, затем закрывает браузер и свой Vite-сервер. Если порт занят, выполнение останавливается. Чужой сервер не переиспользуется. Существующие три снимка заменяются.

- `shelf-home.png`: исходная коллекция четырёх профилей.
- `shelf-detail.png`: страница ненастроенного веб-проекта и диагностическая панель.
- `shelf-setup.png`: пустая форма настройки веб-проекта.
- `hero.svg`: оригинальный векторный заголовок в палитре приложения; не скриншот.

Проверьте изображения глазами перед commit: читаемость, отсутствие личных данных, корректный demo-контекст и актуальность интерфейса. Не подменяйте неизвестные проверки зелёными статусами ради презентации.

## Принципы оформления

Изучены публичные страницы репозиториев:

- [LocalSend](https://github.com/localsend/localsend): короткое объяснение продукта, визуальная демонстрация, установка и описание устройства.
- [Tauri](https://github.com/tauri-apps/tauri): быстрый старт, требования платформы и отдельная архитектурная документация.
- [Hoppscotch](https://github.com/hoppscotch/hoppscotch): узнаваемое вступление, сгруппированные возможности и быстрый переход к документации.

Для Shelf применены эти структурные приёмы, а не чужие иллюстрации, логотипы или рекламные формулировки. Скриншоты и SVG хранятся в репозитории: внешние сервисы бейджей, аналитики и рендера схем не нужны. Mermaid-схему отображает GitHub. Техническое руководство сохранено отдельно, чтобы главная страница оставалась обозримой.
